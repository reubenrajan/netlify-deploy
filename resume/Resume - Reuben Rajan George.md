## Patents

**US10459835B1 — System and Method for Controlling Quality of Performance of Digital Applications** *(Granted October 2019)*
An automated performance engineering system that uses AI-trained bots to test web and mobile apps under simulated real-world conditions (network, CPU, memory, battery). Detects performance issues, classifies them by urgency (immediate, short-term, long-term), auto-applies front-end remediations (image compression, unused code removal, JS optimisation), and validates improvements via before/after metric comparison before production deployment.

**US20230315954A1 — Dynamic Failure Mode Effect Analysis and Recovery Process Recommendation for Cloud Computing Applications** *(Granted October 2023)*
A dynamic risk analysis engine for cloud-native and IoT/edge systems that uses ML to identify failure patterns from historical operational metadata across a device hierarchy. Assigns Risk Priority Numbers (RPN) based on severity, probability, and detectability, then recommends context-aware recovery processes optimised for minimal latency and compute overhead, maintaining a knowledge base of failure patterns for continuous improvement.

**US20240168857A1 — Utilizing Digital Twins for Data-Driven Risk Identification and Root Cause Analysis of a Distributed and Heterogeneous System** *(Granted May 19, 2026)*
A digital twin architecture for hybrid cloud environments where individual component twins feed operational metrics and functional logs into a central coordinating twin. Uses PCA (reconstruction error analysis) and Self-Organizing Maps (SOM) for anomaly detection, then generates a KPI cause vector to trace root causes iteratively across causality levels — enabling preventive action before failures propagate in edge-cloud and heterogeneous distributed systems.

**US20240403135A1 — Cloud Fitness Engineering** *(Published December 2024, Pending)*
An ML-driven system that identifies optimal cloud architectures for specific applications by decomposing business performance goals into measurable technical parameters (throughput, latency, fault tolerance, error rates), then simulating candidate architectures under stress conditions (network outages, load spikes, security breaches). A fitness design controller selects the architecture that best satisfies competing constraints and trade-offs — addressing the core problem of one-size-fits-all cloud migration failures.
